# くるっ！おうちでたこやきパーティー (gf-261120-nx3)

- 起動: `index.html` をそのまま開く（file:// / Pages サブフォルダどちらも可、外部読み込みなし）。開発時のみ `npm i && node build.mjs` で `src/` から `index.html` を再生成。
- お話: 生地をそそぐ → たこ等を入れる → 薬味 → **くるっと返すと丸くなる** → 皿へ（最後の1個が転がって逃げる）→ ソース → マヨ（空になってプスプス）→ かつおぶしが踊る → ぱくっ（中の具が見える）→ ごちそうさま → 次の周回。
- 確認したこと: 390×844 で読み込み・開始時のコンソールエラーなし。お話を1回通して最後まで遊び、次の周回開始まで到達。各段階で「光って揺れる道具・光る的・焼けた玉の湯気・約10秒放置で半透明の指のお手本」が出ることを画面で確認。
- 既知の問題: 確認はヘッドレス（ソフトウェア描画・マウス操作）のみで、実機 iPhone/iPad のタッチ・音・フレームレート・画面回転は未確認。音は耳で聴いていない。途中保存からの復帰は場面単位（場面内の細かい状態は標準状態に戻る）。食べる場面の断面は平らな切り口。
- 描画パフォーマンス（iPhone/iPad 向け, `src/core/perf.js` と `src/main.js`）: 描画バッファは約300万px以内で開始（iPad のみ影響、速ければ自動で DPR 2 まで戻す）。動的解像度は画面のリフレッシュ（60/120Hz、低電力モード30Hz は自動判別）を目標に調整。影マップは影を落とす物が動いた/変わったフレームだけ再描画。起動時に全シェーダを一括コンパイルして場面切替時のカクつきを防止。焼き台の穴とマヨ粒のポリゴンを見た目が変わらない範囲で削減（三角形数 約25〜30%減）。実機での fps は未計測。
- 初回起動の高速化（`src/core/background.js`, `src/core/perf.js`, `src/world/textures.js`）: 最初の場面は手続きテクスチャを低解像度（木目 256px など）で作ってすぐ表示し、本来の解像度版は遊んでいる間に1フレーム数msずつ裏で生成して同じテクスチャへ差し替え（シェーダ再コンパイルなし）。起動時の全シェーダ一括コンパイルをやめ、最初の画面に必要な分だけ描画時にコンパイルし、残り（後の場面の道具・具・影用）は 1×1 の描画で数個ずつ裏で温める（指で操作中は休む）。ヘッドレス計測で最初の描画処理開始 約4.8秒→約0.6秒、温め完了後は全場面を通して新規コンパイル0回（以前は4回）。実機での体感は未計測。
