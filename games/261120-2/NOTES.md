# ぷくぷく！きんぎょのすいそうおそうじ（gf-261120-nx2）

## 起動方法
- `index.html` をそのまま開く（file:// でも GitHub Pages のサブフォルダでも動く。外部読み込みなし、1 ファイル約 0.87MB）。
- 作り直す時: `npm install` → `node tools/build.mjs`（`src/*.js` を 1 つにまとめて `index.html` に埋め込む。金魚テクスチャ用の Worker `src/texworker.js` も文字列として埋め込む。実行時のビルドは不要）。

## お話（指 1 本・文字なし）
あみで金魚 3 びきを金魚鉢へ → スポンジでガラスのコケをふく → 赤いポンプで汚れた水をバケツへ → ピッチャーできれいな水を注ぐ
→ エアポンプのボタンで「ぷくぷく」、水が澄む → 鉢を傾けて金魚を帰す（太っちょの琉金が口につかえて「ぽん！」）→ えさをあげて夕方の光でおしまい → 自由あそび。

## 確認したこと（390×844、ヘッドレス Chromium）
- 読み込み・開始時のコンソールエラーなし。
- お話を最初から最後まで 1 回通して遊び、各段階で「次に触る物」が光だまり＋脈動で示されること、放置時に半透明の指のお手本が出ることを画面で確認。
- 通しのあとに入れた小さな見た目の調整（指のお手本を小さく濃く、光だまりを弱く、注ぐ/帰す間は光を消す）は、読み込みと最初の画面・お手本の表示だけ確認し、通しでは遊び直していない。

## 既知の問題
- 実機（iPhone / iPad）では未確認。速度はヘッドレス（ソフトウェア描画）でしか見ていない。動的解像度は 60fps を目標に下げ、下げても速くならない時（省電力モードの 30fps 上限など）はそれ以上下げない。
- 音はすべて手続き合成で、耳で聞いての音量調整はしていない。
- 縦画面では、えさの段階と自由あそびの構図で水槽がやや小さく、下に棚の前板が広く見える。
- コケをふいたあとの見た目の変化は控えめ（中のにごり水が残るため）。
- あみを水面すれすれで持つと、袋の中の魚がにごりで半分隠れる。

## 描画の軽量化（見た目・遊びは変えていない）
- 影の地図は 60fps 付近では 2 フレームに 1 回だけ描き直す（遅い時は毎フレーム）。解像度の段階変更で影の地図を作り直さない。
- 金魚のくねりの傾きを数値微分（1 頂点 3 回計算）から解析式に。ひれの法線計算を配列直書きに。魚の更新の CPU 時間がおよそ半分。
- 空の粒子プールは描画呼び出しと GPU 転送を省き、生きている粒の分だけ転送（描画呼び出し 213 → 163）。
- 見えていない物のシェーダも途中で初めて出る前に用意しておく（途中のつかえ防止）。※ 起動を速くするため、今は最初の絵のあとに裏で少しずつ行う（下の「起動の速さ」）。

## 起動の速さ（見た目・遊びは変えていない）
- HTML だけの下地（最初の場面の壁・テーブル・棚の色のグラデーション + 小さな泡）がすぐ出て、最初の 3D の絵が出たらふわっと消える。縦長スマホ・iPad 縦・横画面で境目の高さを合わせてある。
- 重い処理は下地が描かれてから始める（main.js の boot）。順番: 金魚テクスチャの画素計算を Worker へ → 部屋・水・FX → 見えている物のシェーダを先に compile（GPU 側で並行）→ Worker の画素で金魚 → story → 描画開始。
- 金魚の胴・ひれ・目の画素計算（ノイズ）は `fishtex.js` に分け、Worker とメインで同じ関数を使う。Worker が使えない時はその場で同じ計算（旧来どおり）。画素はビット単位で旧版と一致することを確認。
- 「2 フレーム目に全部のシェーダを一度に準備」をやめ、最初の絵は見えている物だけで出す。隠れている物（後の道具の粒子・指のお手本など）のシェーダとテクスチャ転送は、遊んでいる間に 1 フレーム 1〜2 個ずつ裏で用意する。指のお手本の手の絵も裏で作る。
- 計測（390×844、ヘッドレス Chromium のソフトウェア描画。実機より何倍も遅い環境での相対比較）:
  何かが画面に出るまで 約 8.0 秒 → 約 0.06 秒（下地）／ 3D の最初の絵 約 8.0 秒 → 約 6.7 秒／
  金魚 3 びきの用意 約 450ms → 約 200ms（Worker と並行）／ 開始直後の 50ms を超えるつかえ 1 回 → 0 回。
- 実機（iPhone / iPad）での起動時間は未計測。
